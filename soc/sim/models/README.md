# NPU SRAM 功能仿真替代模型

`npu_sram_behavioral.sv` 提供服务器包装层引用的七类 SRAM 宏接口。
选择它后，RTL 功能仿真不再需要对应的数千行 SRAM 厂商模型。
端口和正常模式的高有效使能约定以本项目保存的 `NPU_sram_asic_2p.v`、`NPU_sram_asic_sp.v` 为依据；尚未与厂商模型做等价验证。

| 宏 | 存储规格 |
|---|---|
| sram2p8x128 | 8 × 128 |
| sram2p64x128 | 64 × 128 |
| sram2p1024x32 | 1024 × 32 |
| sram2p256x64 | 256 × 64 |
| sram2p32x59 | 32 × 59；服务器包装只使用低 16 个地址 |
| sram1p128x32 | 128 × 32 |
| sram1p32x32 | 32 × 32 |

## 行为约定

- 双口为独立时钟的一写一读：`CLKA` 上升沿在 `MEA && WEA` 时整字写入；`CLKB` 上升沿在 `MEB` 时读取。允许不同地址同时读写。
- 单口在 `CLK` 上升沿、`ME=1` 时操作：`WE=1` 写入，`WE=0` 读取。
- 读输出在采样上升沿后以非阻塞赋值更新；未使能读时保持输出。单口写入也保持旧输出。
- 存储和读输出均不初始化、不增加复位清零；四态仿真中未写存储读出 X。
- 使能读取时地址含 X/Z，输出 X；使能写入时地址含 X/Z，或有效操作控制含 X/Z，终止仿真，避免隐藏不确定写入。
- 双口同一仿真时刻对同一地址读写时终止仿真。检测只覆盖重合边沿，不模拟真实宏的碰撞时间窗，也不把任意 old/new-data 结果当作硬件保证。
- `LS/DS/SD/TEST1[A/B]` 必须保持 0；其他状态在时钟沿触发错误。低功耗、测试模式需后续专用模型或真实宏验证。
- `RME/RM` 等读裕量控制接受连接但不改变功能，不检查其工艺时序效果；这也不能替代对服务器 `RMBE/RMEB` 拼写问题的修复。

## 选择方式和边界

从仓库根目录编译时，可使用 `-f soc/sim/filelist_sram_behavioral.f`。
该清单只包含 SRAM 模型，项目现有活动清单没有自动切换。
服务器 ASIC 包装层还需要 `ASIC`、`SMIC40LL`、`SYNOPSYS_MEM` 宏；标准单元分支应按实际配置选择。
不要同时编译本文件与包含同名模块的真实 SRAM 模型。

这些代码用于 RTL 功能仿真。它们不提供 PVT、建立保持检查、SDF、真实功耗/休眠/保持行为或 FPGA BRAM 映射保证。
FPGA 分支仍调用 `NPU_sram_fpga_* -> syncore`，添加本文件不会修复其已发现的问题。
NPU 顶层、门控/MUX 单元和完整 BIST/SoC 集成仍是单独的依赖。

测试命令（需要 Icarus Verilog 和 vvp）：

```sh
python3 soc/tools/test_sram_models.py
```

可用 `--iverilog`、`--vvp` 指定工具，`--ivl-base`、`--vpi-dir` 指定独立解包的 Icarus 运行目录。
测试包含七类宏的全地址读写、使能和输出保持、未知值、并发与非法模式检测，并检查与服务器 ASIC 包装层的端口绑定。

也可在 `soc/` 下运行 `make sram-model-test PYTHON=python3`，附加参数通过 `SRAM_TEST_ARGS` 传入。
本次以 Icarus 10.3 四态仿真完成：七类宏行为检查、13 个拒绝非法操作的场景、七组服务器 ASIC 包装参数的展开检查。
这不代表已完成 BIST、完整 NPU 或 SoC 计算回归，也不代表厂商宏等价性已验证。
